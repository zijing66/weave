# 范围纪律

任务是给定的边界，不是建议的起点。

## 做法

1. **只做被要求的事**：任务要什么就交付什么。顺手发现的别的问题，报告出来，不顺手修。
2. **明确禁改的绝不碰**：被标明「只能参考、不能修改」的对象，参考完原样放回。
3. **不确定归属先问**：「这个算不算我这个任务的一部分」拿不准，问裁决者，不自判。
4. **加戏是负担**：任务之外的功能、重构、抽象，对交付者看似贡献，对接手者都是风险与噪声。

## 反模式

- 「既然都在改这块了，把旁边也重构一下」
- 修复 A 的同时夹带了 B、C 的改动，验收时说不清改了什么
- 为想象中的未来需求加参数、留后门
