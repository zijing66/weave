# 抽象共性

重复是信号：同一件事出现多次，就该有唯一的模板。

## 做法

1. **先允许重复**：相似的事出现两三次内，先照抄完成，确认它们真是同一件事而不是貌合神离。**不过早抽象**——为「将来可能」的共性建框架，多数会错。
2. **确认真重复后收口**：共性提取到唯一的模板/唯一实现处，后来者只填真正不同的部分。收口点对内是唯一权威：改共性只改这一处。
3. **差异参数化，不复制粘贴**：各实例的差异做成参数/适配层挂在模板上，而不是复制一份模板改几处。
4. **新成员走模板**：再遇到同类对象，用模板生成，不手抄兄弟实例。

## 反模式

- 三处复制粘贴，改共性时漏改一处，口径漂移
- 一次性需求就上抽象，模板只有一个使用者还带着用不上的参数
- 抽象层知识散落多处，谁也说不清唯一权威在哪
