# 完成＝已验证

「做完了」是一个需要证据的结论，不是一种感觉。

## 宣称完成前过两道闸

1. **实证**：有正面验证证据——真的跑过、看到真实输出，而不是「东西已经改了所以应该好了」。代码改完 ≠ 生效；方案写完 ≠ 落地。
2. **对账**：对照当初的目标/验收口径逐条核对。不是「做完了手上的事」，而是「答应了的事都闭环」。答非所问的完美执行仍是未完成。

## 失败处理

- 验证失败就如实报告失败与现象，不修饰、不静默重试。
- 同一验证 2–3 次不成，换思路或上浮请示，不无限重试。
- 跳过或部分验证的，明说哪部分没验证，不许含糊带过。

## 反模式

- 「应该可以了」「理论上没问题」当作完成依据
- 清单打了勾但每一项都没有实证
- 把过程跑得很漂亮，但当初要的结果没交付
