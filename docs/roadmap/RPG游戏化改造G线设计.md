> 状态：设计定版（产品所有者已批准——六星过审 + 效率四件套 + 持久化与清理机制已并入，2026-11-08）。G1 待开工令。

## 一、Context：重定位

weave 从「多 agent 管理看板」升级为**俯瞰像素 RPG 形态的 agent 协同世界**。红白机时代的俯瞰像素风（Stardew Valley / RimWorld / 自走棋的策划与视觉参考，适配 weave 语义）。渐进式：G1 静态画+热点起步，tile 行走后置。

**世界观四层**：

| 层 | 游戏概念 | 现实对应 |
|---|---|---|
| 上帝（用户） | 有化身。Home 室内+协同房间内均自由活动；房间里团队/角色相对固定席位（自走棋盘位），上帝全场自由。**上帝在不同项目中有分身 = 协调者**（2026-11-08 用户裁决：用户掌控的上帝角色，不是独立第三方 agent） | 决策分级路由的级2 唯一落锤人 |
| 角色 | 完整打包的项目（内建仓库隐藏项目+技能集+插件）= agent 人格单元 | RPG 域既有 roles |
| 房子 | 项目组合：1 核心工作空间 + N 辅助项目 + team/角色入住；**同一张 houses 表**，单项目房=退化态（core=自己） | 新实体（收敛多裁决） |
| 世界 | 室外俯瞰地图（Home 的门走出）：宅基地、修炼点、既有项目房子 | 场景域扩展 |

**核心工作空间语义**（用户原话定案）：已有项目是「一个整体的核心工作区/要修改的代码区域」，其他项目的能力都是为核心服务的。

team 管理在 Home 视图（用已有角色组建多队）；**team 名册 live 展开**（队员增减房间即时跟随，不拍快照）。

**Home = 上帝的统一控制台**（2026-11-08 用户裁决）：协调者分身编辑、创建角色、team 管理、任务管理都收进同一张 Home 视图，不开散装入口。**任务管理额外全局面**——任意场景可唤起（不锁 Home），归 G6 任务沙盘一并做（全局面板/常驻一角形态，见 §八）。

## 二、协作四原语（通用 N 角色协作模型）

角色**无类型**（homogeneous）——「开发/测试/审校」不是角色类型，是图位置。「怎么协作」= 配置（拓扑画在编排图上），不是代码。

任何协作分解为四个原语：

1. **产出 = commit**：角色贡献物化为自己 worktree 分支上的提交（分支名如 `role/<char>-<topic>`）
2. **通信 = 编排边**：就绪通知带 `{commit}` 变量（编排边正文变量既有机制）
3. **消费 = 拉取（服务端机械化，三层闭环）**：编排边可选字段 `pull: {ref}`——投递时服务端在目标角色 worktree 内代跑 git（merge/checkout 指定 commit，**只在角色自己的 worktree，不碰主仓**）；**不靠 prompt 教模型自觉拉**（评审②采纳）。同仓 worktree 共享 refs/object store——拉取零同步协议。冲突三层闭环（2026-11-08 用户裁决①「能完整自动闭环才同意」）：**第 0 层机械**（干净 merge/快进即成功）→ **第 1 层 rerere 先例重放**（同形冲突自动消化，标记「rerere 重放」）→ **第 2 层大模型修补**（fork 会话拿冲突文件+两侧 commit message/边正文，三选一：解冲突提交（标「AI resolved」入决策日志）/ 判不可解上报 / 反向打回作者；失败超时走上报兜底）。AI 修补成功两次才进 rerere cache（防一次乌龙被永久重放）；fork 修补每冲突一次走预算闸。**级2 冲突刻意留给上帝**——模型判「涉价值冲突/意图相悖」的，自动闭环不等于无条件闭环
4. **集成 = 合并梯节点**：快进 → 直并+rerere → mergiraf → AI 修补（三层闭环）→ 冲突带报告打回（缓做池的合并梯/mergiraf/冲突雷达捞入 G 线）；同形冲突重复 ≥K 次（rerere 都没救的）升级直报上帝

**可见性铁律**：只见消息/refs/晋升产物；永不读对方工作区、永不写对方分支。绝不跨目录路径引用（软链方案已否决：路径归因系统全灭——pane 定位/事件白名单/文件索引全按路径等值）。

**典型拓扑**（同一引擎的不同图）：流水线（开发→测试相邻节点）、复审总线（扇入逐份裁决）、自由市场（角色→就绪通知→集成节点定序并入、冲突打回反向边）。回归循环由既有 `ORCH_MAX_DELIVERIES` 兜底。

**rerere 局部**：只在 weave 管的 worktree 里 `git config` 设置，不动用户 `~/.gitconfig`（评审⑦采纳：autoupdate 副作用）。mergiraf 缺席如实进能力面回落。**rerere 容量阈值**（用户裁决：达阈值人工决策，不自动清）：先例过 2000 条时提醒——**双落地**：游戏视图（信箱/任务卡）+ **项目视图补充提醒**（核心仓每项目唯一，项目行即该仓维护面的天然提醒位）；清不清理由人裁（rerere 记忆越多越值钱，占空间由用户权衡）。

**效率补丁（2026-11-08 用户裁决，四件套）**——自治体系的「经济性」防线，防「简单工作上复杂编排」的仪式成本倒挂：

1. **任务分级路由**（先分流再动手，2026-11-08 用户修订④判断层）：轻（单步可完/单文件/可逆——**直接干不上 goal 图**，一回合内 commit 即产出）/ 中（多步线性——哑推进边，自查密度按档位配）/ 重（多角色/不可逆风险——完整体系）。**分流判断 = 三档瀑布**：优先决策模型 → 降级 fork 子模型 → **最低硬规则启发式兜底**（文件数+步骤数+可逆性阈值表，零智能但永远在场——模型全灭时分流仍产生，不因「判不了档位」卡立项）。

**goal 立项终态闸**（2026-11-08 用户修订⑤：任务定下时必须有任意维度的明确可终止条件——没有终态的目标立项即浪费）：三入口——**A 用户下达时明确指定**（任一维度：文件/合并/测试通过/命令退出码/可验收产出，自由但必须明确）；**B 未指定则模型补全**：启发式提问（问用户「做完的标准是什么」，一两轮收敛）→ 决策模型判断「这是否终态明确的 goal」→ 明确则建议标准请用户点头；不明确则继续问或**建议拆分为子目标**；**C 无法明确化 → 不立项**（永不收敛目标进不了体系）。终态与预算可量化复合（「终态 = X，预算上限 Y，先到者为准」是合法形态）。
2. **批结算模式**（防每产物独立全链的浪费）：产物先落角色 worktree 分支（产出即 commit 原语不变），**不立即触发合并边**；**收批由用户主动在界面触发**（链路卡上的「收批」入口）+ 自动时间窗兜底（缺省 30min 空闲 + 簇上限 8，进策略档可进化）。收批时一次性：相似度聚簇（按文件域/功能域）→ 近似功能多 commit squash/重排成净历史 → 一次合并梯 → 决策日志按簇落账。缓冲落 `cache/`（内存只作热加速），**收批落地即清空**（事务性：批并完→清空→防半批状态）。
3. **修订折叠**（防「改了又回退又接着改」污染记录）：任务卡/决策日志时间线**默认按净变更显示**（`+u -u +u` 四连 commit 折成「最终定案 u，经历一次返工」），点开才展开明细——**审计链完整保留，只折叠显示，不篡改历史**（rebase 篡史危险，我们不篡改）。
4. **抖动检测**（与循环检测同一指纹架构扩展语义，2026-11-08 用户修订：一般抖动自闭环、无需用户终审）：同一文件/决策点窗口内**净变更量≈0 但动作量高**（改+回退+改）= 抖动，三级递进——**①自愈窗口**（什么都不做只观察，正常返工自己收敛）→ 持续未收敛 **②AI 闭环**（协调者级1 三判：正常迭代节奏→延长观察窗；无意义反复→**冻结该决策点一个冷却期**+通知角色换思路（可逆，级0）；目标本身冲突→升级）→ 仍不收敛且属目标冲突 **③用户终审恒呈级2**（「卡住需人拍板」才有资格到这）。事后分析挂点（回合收尾事件账+git），不打断在跑的活。

## 三、出征与 kit（方案 C，B5 演化）

**出征 = 给角色在目标项目上开 worktree 会话**（`git worktree add` 一条分支、会话 cwd=worktree 路径、sessionEnd 合并——B5 既有机制）。**并回目标分支 = 出征起手时快照锚定的分支**（用户裁决②：锚定后用户切走分支不影响闭环——并的是快照 ref 不是「当时的当前」）。B5 原有冲突行为（不并保留上报）= 合并梯最后一档。

**锚定悬空救援**（用户裁决②场景 C——锚定分支被删/重置时合并断裂）：挂起合并不改写历史（角色提交作为孤儿仍在 object store，活不丢）→ 生成「锚定悬空卡片」进任务卡/信箱（哪次出征、锚 branch-x@sha、悬空分支指着哪、推荐去处清单）→ 三选一：并回同名新分支（未分叉可自动走，分叉了呈级2）/ 并回主分支走三层闭环 / 冻结 worktree 待定（级2）→ 待裁决期间角色 goal 循环不受影响。

**合并链路卡**（用户裁决②可观测要求——人机共读同一份底账）：任务卡·现场 tab 的子版，把一次出征全链路渲染成链路图：出征编号/分支/锚定快照×原始任务正文（「你当时说: …」）→ 合并每一层的动作与结果（机械/rerere/AI 修补各层带理由，如「a.ts: 两侧都要保留，合并为依次调用」——**模型判的理由原样展示给人**）→ 场景提示（如「你 14:32 重置了 branch-x」事件账源）。底层数据 = 决策日志 detail + 事件账时间戳 + git 快照三者共用（机器读的结构化记录直接渲染成人话卡片，不是平行账本）；冲突文件可下钻 diff（复用 edits 槽渲染器）。

**kit 三层**：

| 层 | 本体 | 出征携带 |
|---|---|---|
| 人格层 | persona | **skill 形态安装**（一防止压缩丢失——用户修正裁决：引用路径扛不住 auto-compact；skill 落盘+清单进系统区则压缩后在场） |
| 技能层 | SKILL.md+脚本 | **出征即安装**（同上理由） |
| 能力层 | MCP 插件/密钥 | **不随行**：需要时走晋升安装到目标项目档，绝不跨项目借用 MCP 连接（E4 收口红线同源） |

**落盘与静默**：kit 装进 worktree 专用子目录 `.claude/skills/<role>-<skill>/`（角色名前缀防撞名）；`.git/info/exclude` 追加带 marker 的块（`# weave:role-kit:<role>:<出征实例id>`），幂等、块状增删。**exclude 编辑串行化+登记文件即引用计数**（评审⑤采纳：同角色双目标并行出征、跨出征窗口撞名、并发写 exclude 都闭环）。exclude 条目只对 untracked 生效——**kit 路径与核心仓已跟踪路径查重是硬前置**。

**CLAUDE.md 双路**：项目 track 了 CLAUDE.md → 一个字不碰（人格走 skill 形态）；untracked → 写临时 CLAUDE.md（exclude 静默）。（CLAUDE.local.md 现行支持 = 实现批待勘项。）

**sessionEnd 清场**：清 kit + 摘自己的 exclude 块（引用计数）；**验证判据含已提交内容扫描**（评审⑥采纳：防 agent 把 `.claude/skills/` commit 进分支后被合并「合法」带入）——合并前扫已提交的 kit 路径，不得出现角色仓库来源文件。

**skill 执行状态外置**（superpower 型流程 skill 的冗余执行补丁，用户裁决）：流程性 skill 的进度态**不靠会话上下文记，落盘成结构化状态文件**（worktree 内 `.weave/skill-state/<skill>.json`）——每拍执行前读状态，**已完成步骤直接跳过不重读**（同「skill 落盘防压缩丢失」同源同解）。配套铁则：①凡 kit 流程性 skill，**步骤必须幂等可跳**（每步自带完成判据）；重入检测到「状态说做过但事实无效果」时，重跑贵的问级1、便宜的直接重跑。②自主推进边带「本轮已载入 skill 集」标记，跨拍免重载 SKILL.md 全文。

**kit 能力分派（MCP vs skill+CLI 选型铁则）**——背景：MCP 常驻 schema 300–1500 token/工具（与是否使用无关），skill 清单薄、按需载入；决策律 = 常驻成本按调用频率摊销。四形分类：

| 形 | 定义 | 判据 | 例子 |
|---|---|---|---|
| **A MCP（服务型）** | 需跨调用会话状态/进程宿主/复杂协议 | 状态轴=是 | weave 四服务（A1 状态型，仅协调者默认装）、协议型（A2 系统级不装入 kit）、高频结构化（A3 按房级 .mcp.json） |
| **B Skill 文档形** | 一套知识/说明书 | 形态轴=知识 | 方法论（督导/破局/降级）、规范词表、本机领域事实 |
| **C Skill+CLI 命令形** | 薄工具：单发查询/单发动作/组合脚本 | 状态轴=否 且 频率轴=否 | git 查询、构建一次、隐私扫描 |
| **D 内置函数** | 热路径机制/纯函数判定/安全边界——不暴露给模型 | 都不是 | ingest 投递、排序器、token 校验 |

分派决策树四关（按序）：要会话外状态？→是= MCP；否→是知识还是动作？知识=Skill 文档；动作→高频且参数复杂？是= MCP（限协调者/house 级）；否= skill+CLI。**违规惩罚三档**（用户裁决③）：C 类薄能力包装成 MCP（钻 token 闸空子）→ 品阶降档；B 类知识形开进程 → 品阶降档；A 类真需状态的能力 skill 化失败（框架没接住，非故意）→ 首犯只警告+决策日志观察，不降档。品阶降档本身是级0 动作（纯度量，协调者直接执行，不占级2）。协调者会话上下文 MCP schema 占比超 40% 触发瘦身观察（进决策日志指标）。

## 四、goal 模式（角色自治）

**goal = 编排引擎上的另一种图，与普通编排正交不嵌套**（用户裁决④：两者是不同层次的概念，不是父子关系）。同一引擎机制底座（图/节点/边/投递/冷却/闸），两种图：

- **普通编排图**：用户手画的固定流水线（「开发完→跑文档记录」），描述**事怎么流转**，跑完即止、与 goal 无关、可独立存在
- **goal 图**：goal 节点为入口 + 自主推进边（无正文只带冷却）+ 角色节点，描述**角色朝目标怎么活**，长期驻留直到达成/预算尽/撤销，驱动三岔口循环

**角色可同时处于两种结构**：某普通编排的被动节点 + 某 goal 的自主执行者——互不干扰（不在一个维度上）；两种活动的产出都走四原语。「触发/过滤唯一配置入口=编排画布」的 CLAUDE.md 站立规则原样成立（goal 图也是画布上的一种图）。

上帝设整体目标（挂 house/role 表单，**立项即过终态闸**——见 §二 效率补丁⑤：无明确可终止条件的 goal 不立项），角色自主推进；**三岔口自查**（persona 契约，prompt 层）：顺畅继续 / 无法决策上报（级1→级2 两跳，见决策路由）/ 里程碑收官播报——**收官判定 = 立项时定的终态条件命中**。

**失控兜底三闸**：
1. **预算闸**：每角色每 goal 回合数+token 双闸，到顶暂停+上报「要不要续期」
2. **无进展熔断**：连续 N 拍零 commit 零产物零事件量 = 判空转，暂停+上报
3. **预算期间决策翻案权**：上帝一票推翻即时回滚（红线）

## 五、死循环检测与协调者

**机制层硬检测**（无协调者也运转，挂在引擎事件流后台算，不在 hook 路径上）：

| 信号 | 判据 | 动作 |
|---|---|---|
| 重复度指纹 | 回合收尾算「所动文件集合+message 摘要」指纹；N 拍内同指纹 ≥K 次打转 | 暂停 goal+循环检测报告 |
| 无进展熔断 | 连续 N 拍零产出 | 暂停+上报 |
| 投递环闸 | `ORCH_MAX_DELIVERIES`/`ORCH_MAX_FORKS`（既有） | 到顶拦截 |
| 同形冲突重复 | 集成节点同文件同区间冲突 ≥K 次 | 升级直报上帝 |

**协调者 = 上帝在不同项目中的分身**（2026-11-08 用户裁决语义定版：用户掌控的上帝角色——分身是上帝意志在各房的执行化身，不是独立第三方 agent；「常驻进化体」的自治职责全部落在分身上、受上帝掌控）：
- **每房必有分身**。分身与角色同等待遇：kit 同步进 worktree（三层同用）
- **唯一特权 = 接入 weave 内置 MCP**（四服务：项目/角色/会话/投递）——全局控制的实权来自 MCP 工具面（与 E4「内置 MCP 收口项目档」闭环：所有角色都能装，唯分身默认装）
- **权限界**：用户掌控——级0/级1 日常动作（巡房/派活/催进度）分身可代跑，**级2 八条清单恒呈上帝本体（用户）**（用户裁决⑤：非必要权限放 AI，只重大决策用户确认）。「全权但受路由约束」
- **担任软检测**：督导（每 M 拍巡回，级1 判断离目标远近）、破局（循环报告→建议初稿）、降级（不可达判定→降标/换法/放弃建议）——三枚出厂 skill，走 kit 同一通道
- **分身编辑在 Home**（统一控制台入口，见 §一）：各房分身的人格/分寸/待批清单的查看与改动
- **项目级自进化 = 分身**（复盘本 house 决策轨迹→提案→呈级2）
- **全局采集与记忆 = 本体**（跨 house 手法库：什么套路在什么场景跑赢）

## 六、决策分级路由（含自进化）

**任何决策点必须有序降级路径**（决策模型弱依赖为不变式——任何一级缺席只是「降级到更贵的判断」而非链路中断，与 hooks 非阻塞、投递瀑布同构）：

```
级0 无判断  → 规则/配置直接定（拓扑序、命名前缀、冷却跳过）——零智能
级1 有判断但可逆便宜 → 决策模型优先 → fork 回落 → hold 等上帝（ConditionJudge 既有瀑布）
级2 不可逆/价值敏感 → 上帝（晋升/目标变更/预算续期/降级/天品验收/跨机邀请）
级3 机制熔断 → 不问任何人（超限/环闸/无进展/指纹）
```

路由判据（用户裁决⑤精调：**非必要的放 AI，只重大决策用户确认**——级2 判据 = 不可逆 ‖ 跨边界 ‖ 价值敏感，三选一）：无判断→级0；可逆便宜→级1；不可逆/跨边界/价值敏感→级2；重复/超限→级3。

**级2 清单定版（八条，用户必须确认的全部）**：晋升进核心工作空间 / 目标变更与 goal 撤销 / 预算续期 / 降级裁决 / 跨 house 写与全局配置改动 / 删除或冻结角色及持久记忆 / 天品验收 / 跨机联盟动作。**放给 AI 自主的**（原设计保守处按⑤精调放出）：协调者日常调度（巡房/派活/催进度）、合并三层修补自动重放、品阶凡/灵/仙自动评定、任务卡挂起恢复、凡品产物自产自销、锚定悬空的未分叉自动并回。**协调者可预告级2动作**（聚成待批清单进信箱，用户择机批）——但**执行权恒等用户**（与「新挂起待答只提醒不自动弹」既有口径一致）。

**决策日志**（新增一张账，`routing_decisions`）：路由级/判定依据/输入摘要/结果/翻案标记——挂在既有 `ConditionDecision` 的 source/detail 形状上。**保留期 = 会话生命周期**（随会话归档过期，用户裁决）；**唯持久记忆不灭**（见下）。

**决策进化闭环**：复盘（扫决策轨迹：翻案率/误报率/阈值命中）→ 提案（级1 出调参草稿）→ 裁决（级2 上帝点选采纳/拒绝/改参数）→ 策略档（`routing_profile`：路由阈值/置信度/各角色分寸，版本化可回滚）。**三红线**：提案永不触碰级2 清单（安全边界非参数）；策略档版本化一键回滚；进化频率有闸。rerere 是同哲学先例（先例复用，git 层与决策层成对）。

**持久记忆**（用户裁决 2）：会话/decision 账可过期，**唯「进化产出」持久**——落**项目相关文件夹**（协调者本体 = 全局手法库目录；分身 = 巩固进角色仓/本人 house 相关目录），**可迁移**（角色仓搬走记忆跟着走）。形态 = Claude Code memory 目录约定同款（`MEMORY.md` 索引+单事实单文件+frontmatter+`[[]]` 织网）；mem0/Letta 等重型框架（mem0 论文量化 +26%、Graphiti 时序图）**列为观察项不引入**（伞包自包含红线）。

**持久化总纲与清理机制**（2026-11-08 用户裁决：「所有操作避免内存记录，daemon 重启可及时全量完整恢复」+「注意无效过时数据清理」）：

- **持久化总纲**：运行时状态二分——**事实数据**（必须可全量恢复）一律持久化（goal 循环走落库图 rearm、批缓冲/skill 状态落 `cache/` 与 worktree、策略档落盘版本化）；**性能热层**（指纹缓存等）内存合法但必须有磁盘母本+全量重建路径（推导源全在盘上：事件账+git——重启后重算即恢复，非增量）。daemon 重启 = 全量恢复语义。
- **权威 vs 推导物二分**（清理的总原则）：事实数据按自身生命周期过期（会话期/任务终态）；**推导物**（指纹缓存等可再生结构）永远可以大胆清——低于积极清理成本的推导物只在重建时顺手清（lazy），事实数据绝不混用这套大胆策略。
- **清理机制全景**：决策日志随会话归档过期（既有）；批缓冲**收批落地即清**；skill 状态文件随**任务终态**清（终态 = goal 达成/撤销/预算尽 + run 全部收尾；孤儿态周期清扫）；指纹缓存窗口滚动（旧窗口淘汰，重建时 mark-and-sweep）；策略档/持久记忆**不定期删——走记忆剪枝**（复盘闭环的一部分：失效先例按翻案率淘汰，进提案通道）；kit/worktree sessionEnd 清（既有）；rerere 达阈值人工裁（见 §二）。**清理动作恒幂等**（mark-then-sweep，中断重跑不损）。
- **超标提醒双落地**（用户裁决）：凡清理相关需人知的提醒（rerere 阈值、批缓冲积压、孤儿态堆积），游戏视图（信箱/任务卡）+ **项目视图补充提醒**双路下发——核心仓每项目唯一，项目行是维护面的天然提醒位。

## 七、修炼玩法与产物

- **生长 = 事实驱动**（星露谷日程钟否决）：一株作物 = 一次真实构建/生成回合，生长阶段 = 事实发展阶段；季节只作视觉皮肤
- **产物落角色仓库**；**晋升三档** = 既有三层安装位游戏化（核心工作空间项目档 → 内建仓库 → 全局用户级）——晋升是级2 人工裁决（收菜那一刻）
- **质量档 = 修真品阶**（用户选 A）：凡品=能跑 / 灵品=带测试 / 仙品=过全门（lint+测试+文档）/ 天品=用户手验。灵/仙系统按真实度量自动评定（档位不自封）；仙品信号源=hook 事件账的结构化测试/lint 结果（实现批勘验）；天品人工
- **资源系统**：token 预算=体力（进计划；与决策日志预算闸同一套）
- 咬钩时刻=产物验收交互（钓鱼拉条 → 上帝看摘要点收/放回）；照料介入=构建失败「该浇水了」通知

## 八、任务沙盘

任务 = goal 的呈现：**goal → 任务（阶段）→ 回合（run）三层**；手动投递也可直接建任务。

任务卡 = **锚到既有场景 + 详情弹层三 tab**（现场=潜入角色/house 场景高亮干活角色 / 时间线=run 历史+决策轨迹**（默认净变更折叠视图，点开展开明细——见 §二 修订折叠）** / 生长=产物状态），不新造场景实体。进度从 hook 事件账+activity 合账派生（无轮询）。**进行中任务在上帝 UI 常驻一角**（宠物式聚合）。**任务管理不锁场景**——任意视图可唤起的全局面板（2026-11-08 用户裁决），Home 统一控制台里也是同一份入口。任务终态锚（= goal 达成/撤销/预算尽 + run 收尾）驱动 skill 状态清理（见 §六 清理机制）。归 G6（按计划进行，不提前）。

**项目视图的角色可见桥**（2026-11-08 用户裁决补全：每个角色的工作/当前模式在项目视图中要有会话对应）——事实基线：出征会话经 `projectOfCwd` 前缀归一落在**目标项目**名下（既有）；驻家修炼会话在隐藏仓**刻意不进列表**（隐藏正确——列表会爆炸）。补的是渲染层聚合，不动的归置：

1. **核心仓项目行 = 该 house 全景提醒位**：行徽章扩为「本项目会话 N + 出征角色 M」（M = 正在为核心仓干活的出征会话数，数据现成={projectOfCwd 归一的会话+worktree 徽章}）；角色带回合状态（战斗中/待命）。
2. **关联角色折叠区**：项目行点开 = 该 house 成员角色的 currentState（谁在修炼、钓鱼、钓到什么档）——数据源 RPG 域既有（roles+最后会话派生态），零新表、纯 web 层。
3. **角色版双路提醒**（进 G6）：凡落在角色头上的（goal 三岔口上报/预算续期/降级/收菜/终态达成），游戏视图信箱 + 该行折叠区角标两处同发；离散状态变化走既有 watch 三腿。

**自动化命名铁则**（2026-11-08 用户裁决：项目会话列表里凡是自动化的一眼可辨）：

- **统一前缀 `[weave]`** + 语法 `类型·主体·语境`：出征 = `[weave] 出征·<角色>·<目标简述>`；协调分身例行 = `[weave] 协调·<house>`；修炼 fork = `[weave] 修炼·<角色>·<作物>`；决策/修补 fork = `[weave] 决策·…`/`[weave] 修补·<文件>`。类型词表进 core 表（`HARNESS_SESSION_CONTROL` 邻位，词表进表不散写）。
- **命名唯一拼装点**（同 `sessionWorktreeDir` 先例）：一处常量函数，全自动化入口调用；写的是 sessions 域 daemon 侧自留 title（双向 rename 既有机制），**不碰宿主内部文件**。
- **边界**：用户手动重命名后不再自动覆盖（title 不匹配即停写）——标记是自动化的身份牌不是枷锁。见 `[weave]` = 行为预期按自动面（既有「手动面 vs 自动面」区分在列表层的延伸）。run/投递不建会话——不占名字空间。

**G2.6 资产化裁决（2026-11-09，用户定案「需要，且渲染性能/避免卡顿最优先」）**：
- **资产选型 = Kenney Tiny Farm（CC0）为基底**——合规核查：Kenney 全库 CC0（零署名义务、可进伞包分发）；Sprout Lands 免费版要求署名（备选，若观感胜出再走 LICENSE/关于页署名方案）；itch.io「free」≠ CC0 逐包核查成本高。下载后先验包内 LICENSE 文件与内容再动代码；资产文件落 `web/src/assets/` 打进 dist（自包含红线不破，运行时零联网）。
- **渲染引擎裁决 = 现在不引游戏框架（PixiJS/Phaser），给触发线**：①profile 实测世界层持续掉帧（<50fps）或交互延迟 >100ms；②地图规模 >~5000 tile；③需要逐帧粒子/光照（如昼夜循环）——到线升 PixiJS（canvas2d 渲染器）而非 Phaser（只取渲染层，不取场景管理，与 walker 纯函数/React 域兼容）。理由：静态箱庭 = 世界层单合成层 + transform scale 纹理采样，不动零重绘；常驻 rAF 渲染循环与「无人在看不空转」纪律相悖。
- **资产化性能纪律**：图集 + `background-position` + `image-rendering: pixelated`（不换 canvas，G4 裁决不动）；**按 tile 类型合并 div**（同类型连续格一个 div + background-repeat，1728 → ~200）；动效只走 transform/opacity 合成器属性；世界层 `will-change: transform`；引擎/行走/热点/相机数学零改动（§九「换资产零代码改动」兑现）。
