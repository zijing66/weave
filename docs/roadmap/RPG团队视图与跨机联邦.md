# RPG 团队视图与跨机联邦：落地设计计划

> **2026-10-25 设计稿（未实施）**。用户构想：利用已有 weave 功能作为基础设施，实现
> 所有通用 harness 的 agent 角色 **RPG 游戏视图**（参考 Paperclip）——团队每个角色 =
> 一个具有独立 skill / MCP 等插件化功能的**项目**；默认（或自定义）目录自动创建角色
> 仓库（继承全局通用 skill）；weave 内置**统一协调者仓库**（设计好目录结构、支持整体
> 迁移到自定义路径）；协调者按任务指示创建团队 / 复用角色；页面右上角切换入口进入
> 游戏视角。**更更重要**：增加本地 MCP 发现服务（mDNS 广播，下文称 mTCP 发现），
> 后期支持跨机器会话联邦（`session-orchestration.md` D8 预留）。
>

## 一、核心架构裁决（防 RPG 变成第二个世界）

用户裁决：**需要 L2 编排**——任务引擎 = 既有编排，不新造。由此推出四条落地裁决：

1. **游戏态两分：观察态全派生，行动态落 RPG 域**。观察态（角色状态机 =
   `deriveSessionStatus` 映射：running→工作中、compacting→蓄力、failed→受伤、
   idle→空闲、terminated→离场；XP / 等级 / 成就 = `hook_events` 只读统计）零第二
   数据源；行动态（修炼记录、技巧评分、装扮偏好）是**游戏自己的事实**，落 RPG 域表
   ——判据见第九章「这是游戏的事实还是会话的事实」。
2. **任务 = L2 编排 run**。weaveRPG.md 的任务系统（日常 / 主线 / Boss / 迭代）不新造
   引擎：编排图就是任务的依赖与流程，run 状态就是任务状态，RPG 视图是编排运行态的
   游戏化渲染。L1 扩展点（批 2b 后）提供任务过程中的事件反馈（角色回合结束 →
   任务进度拍点）。
3. **角色 = 项目 + 会话**。角色仓库是一个 weave 项目：独立 skill / MCP / 插件配置落
   项目档，user 档全局 skill 天然继承（既有作用域机制零改动）；角色实例 = 该项目里的
   会话（v1 一角色一会话，转生 / 分身后议）。角色项目在 `projects.meta` 带分组标记
   （字段已有）——dashboard 按组折叠、RPG 视图展开，两视图共享同一份项目注册表。
4. **协调者 = 内置仓库 + 常驻会话**。协调者仓库是 weave 内置资产（对齐内置市场仓
   先例）；协调者会话由 L2 编排驱动（autoFire 自然回合 + 任务指示投递），它用 weave
   MCP 工具（weave-projects / weave-sessions）执行建队与调度——**协调者是 MCP 生态
   的第一个重度消费者**，RPG 计划与 MCP 计划在此交汇。
5. **游戏操作 = 服务端语义门面，门面下恒是既有 API**（用户裁决 2026-10-25）。游戏
   视图的一切写操作先抽象成游戏动词（修炼 / 组队 / 出征…），门面层把动词翻译成
   既有 API 调用并落游戏事实——**零新写实现**：业务裁决（安装校验、投递层序、编排
   触发）全部仍在既有 API，门面只做映射 + 组合 + 游戏事实记录，永不自带裁决。
6. **RPG 代码与既有代码零耦合，经适配层双向交互**（用户裁决 2026-10-25）。RPG 域
   是独立模块（server 侧 `src/rpg/` 独立域 + web 侧 `web/src/rpg/`），**依赖方向
   单向**：`rpg → 适配层 → 既有域`；既有域永不 import RPG（唯一例外 = daemon
   装配点单点挂载，既有惯例）。适配层 = 接口 + 纯函数组装（不新增抽象类，对齐全仓
   红线；形态同 `PluginSurface` / 决策内核先例）：**读侧**给观察态派生素材（会话
   状态、事件统计、工具安装态），**写侧**即动词门面（5.2）。RPG 可整体启停
   （settings 闸，缺省不装 = 零开销），未来可整体拆包甚至独立发布而不动既有域。

## 三、角色仓库（provisioning）

- **默认根**：`<dataRoot>/data/rpg/roles/<role>/`——对齐市场副本先例（weave 管理的
  资产仓库落 `data/`，`libraries.path` 相对基同款），**迁移整档带走**；自定义根 =
  settings 键（`rpg.rolesRoot`），搬迁走 `ensureDataLayout` 纪律（只 rename 从不删、
  幂等、活 daemon 占用则整个不动）。
- **生成** = 角色模板实例化：`weave init`（采集 / hook 面）+ 角色人设 CLAUDE.md +
  角色 skill 落项目档；全局 user 档 skill 既有机制天然继承。
- **模板库**放协调者仓库 `templates/`：基础七型 + 模块叠加（weaveRPG.md 第一章的
  抽象角色组合），模板 = 目录 + 清单（声明该型默认装哪些 skill / MCP / 插件）。
- **复用角色** = 已注册项目直接入队（不重建）；角色退役 = 项目归档（既有
  `archived_at`），不删仓库。

## 四、协调者仓库

内置资产（对齐内置市场仓先例），目录结构：

```
coordinator/
  teams/        # 团队声明：角色项目集 + 编排图引用 + 团队目标
  templates/    # 角色模板（基础七型 + 模块）
  playbooks/    # 任务剧本：Boss/副本的编排图模板（含 when/condition 边闸）
  state/        # 协调者会话的运行素材（任务指示、进度笔记——会话自己的转录之外的工作底稿）
```

- **整体迁移到自定义路径**：settings 键 + `ensureDataLayout` 式搬迁（同上纪律）。
- **协调者会话**：常驻、由 L2 编排驱动——「创建团队 / 复用角色 / 派任务」都是投递给
  它的 prompt；它经 MCP 工具执行（建项目、init、起会话、触发编排）。协调者自身的
  回合是诱导回合（批 2a 登记机制覆盖），不会自触发风暴。

## 五、游戏视图与游戏语义层（web + 动词门面）

### 5.1 游戏视图（web）

- **入口**：dashboard 右上角视图切换（仪表盘 ↔ RPG），**路由化**（位置即 URL，
  `parseRoute` 单向落下）；卡片内部视图态不进 URL 照旧。
- **v1 MVP**：团队俯视视图——角色卡（像素立绘 + 状态映射动画：idle / work / blocked /
  rest）+ 任务栏（编排 run 列表的游戏化呈现）+ 点击角色进**既有**会话详情（不复制
  对话面）。
- **视觉**：像素风 Q 版按 weaveRPG.md 第五章；渲染选型（CSS sprite vs PixiJS）实施
  批定，倾向先 CSS sprite（零新依赖，八条移动端硬约束好过检）。

### 5.2 游戏语义层（动词门面，server 侧）

游戏视图的一切写操作**先抽象成游戏动词**，门面把动词翻译成既有 API 调用（用户裁决：
「例如安装技能接口，在游戏中需要抽象成修炼与经验成长，还有技巧维度的评分」）。
门面落 server（`/rpg/*` 路由 + game-verb service，内部调既有 service / API 逻辑），
**门面就是适配层（第一章裁决 6）的写侧**；web 只发游戏动词，**不拿游戏标签自拼
REST 调用**（否则游戏词汇散进 web，违反 web 只渲染）。

| 游戏动词 | 底层既有 API | 游戏事实（RPG 域表） |
|---|---|---|
| **修炼**（学技能） | 技能安装（market / install skill） | 成长记录 + **技巧维度评分** |
| 进阶 / 换装 | 插件 / MCP 安装（install） | 成长记录 |
| 组队 | 团队声明写（协调者仓库 `teams/`） | — |
| 出征 / 接任务 | 编排触发（trigger） | — |
| 传音 | 消息投递（`MessageDeliverer.send`） | — |
| 点卯 / 休整 | 会话创建 / 中断（既有面） | — |
| 批阅战报 | review 批阅动作（定位稿①） | — |

**技巧维度评分**（修炼的产出）：按七型维度（能量 / 思考 / 创造 / 连接 / 审核 /
执行 / 适配）出分——初始分 = 角色模板基线，后续分 = 修炼后实战表现派生（回合
成功率、任务完成、协作投递统计）回写。评分是游戏事实落 RPG 域表，但**计算素材
全派生**（不新采任何数据）。

**门面的边界**：一个动词 = 映射 + 组合（可一次串多个既有 API）+ 游戏事实记录，
三件事之外什么都不做——安装校验、路径归属、投递层序、编排闸全部留在既有 API。
后期可将动词面经 MCP 暴露（`weave-rpg` server），让协调者 / 外部 agent 也说游戏
词汇（缓做，随 MCP 生态计划评估）。

**红线**：游戏视图零新数据源（观察态全派生）、零新写实现（写操作全走动词门面 →
既有 API）。游戏视图只是「换一双眼睛、换一套词汇看与操作同一份真相」。

## 六、mTCP 发现与跨机联邦

- **mTCP 发现（本地）**：mDNS / zeroconf 广播 daemon 的 MCP 端点（服务类型
  `_weave-mcp._tcp`，实例名带机器标识），LAN 内其他 weave / agent 客户端可发现并
  直连对端 MCP 面。发现服务只广播、不接收执行——安全面不变（对端仍要本机令牌）。
- **联邦（跨机）**：对齐 `session-orchestration.md` D8 预留，不另起炉灶——peer
  daemon 注册表（手动 `host:port` + pairing token；mDNS 自动发现为增强）、
  `MessageRouter`（目标会话不在本地 sessions → 查 peer 表 → 转发）、peer 握手互报
  `messaging/capabilities` 矩阵（远端支持状态同构呈现）。**安全红线照 D8 原文**：
  pairing 显式授权、联邦默认关闭、一期转发仅 inject 模式。
- **与 MCP 生态计划的交汇**：被缓做的**外部 webhook 扇入在联邦下获得第一个真实
  集成方**——peer 间的机器投递走对端 webhook / MCP 入口，联邦落地时一并复活
  （接线清单已在 MCP 分析稿 §1.6 备档）。
- **跨机 RPG**：角色可分布在多台机器（联邦会话同构呈现），协调者把任务路由到远端
  角色——RPG 是联邦的第一个应用场景，也是它的验收场。

## 七、优先级总表（全工作线，含既有定稿）

| 级 | 工作线 | 理由 |
|---|---|---|
| **P0 立即** | review 批阅 + rerere 默认开 + L1 批 1 | 已定稿的快赢；批 1 是后续一切的地基 |
| **P1** | L1 批 2a → 2b；MCP-1 → MCP-2 | L1 是 RPG 任务反馈的事件底座；MCP 是协调者的手（weave-sessions 是协调者调度角色的工具面） |
| **P2** | worktree 最小切片；MCP-3；**RPG-1**（协调者仓库 + 角色模板 + provisioning） | 多角色并行同仓的前提；协调者基建纯增量、不依赖游戏视图 |
| **P3** | **RPG-2**（游戏视图 MVP）；成本面会话级展示 | 视图是纯派生面，P1/P2 地基齐了才不返工 |
| **P4** | **mTCP 发现**（mDNS 广播 + peer 注册表 + pairing）；RPG-3（XP/成就/动画深化） | 发现是联邦前置；网络层独立可开发，价值兑现靠联邦 |
| **P5** | **联邦**（MessageRouter + capabilities 互报 + webhook 扇入复活）；RPG-4（跨机角色） | 执行级信任面，安全红线最重，最后落 |
| 缓做 | 冲突雷达 / 解决会话 / 合并梯排序 / 成本精细归因 / L1 缓做清单 | 已定稿不动 |

排序逻辑一句话：**先地基（L1 + MCP）→ 再并行前提（worktree）→ 再协调者（RPG-1）→
再眼睛（RPG-2）→ 再网络（mTCP）→ 最后信任（联邦）**。RPG-1 故意排在游戏视图之前：
协调者仓库与角色 provisioning 是纯后端增量，可独立验收；游戏视图是它上面最薄的一层皮。

## 九、不做什么与红线

- **不做第二游戏状态源**：一切游戏态从既有数据派生（第一章裁决 1）；发现需要新落
  的事实，先问「这是游戏的事实还是会话的事实」——是后者的去扩会话域，是前者的
  才准进 RPG 域。
- **不做第二任务引擎**：任务 = L2 编排 run（用户裁决）；weaveRPG.md 的任务属性
  （难度/风险/奖励）是编排与角色的**标注**，不是新运行时。
- **不做游戏内写实现**：写操作全走动词门面 → 既有 API（第五章 5.2）；门面永不自带
  业务裁决。
- **RPG 与既有代码零耦合**：一切交互经适配层（第一章裁决 6），既有域不出现游戏
  词汇、不 import RPG 模块；适配层接口是唯一接触面，改 RPG 不动既有域、改既有域
  只动适配层实现。
- **角色仓库不绕过 init 写策略**：`.weave/` 可覆写、用户文件只追加合并。
- **联邦安全红线照 D8**：pairing 显式授权、默认关闭、一期 inject-only；mDNS 只发现
  不授权。
- **v1 不做多实例角色**（转生 / 分身）、不做 RPG 专属 SSE 通道（复用既有帧域）。
