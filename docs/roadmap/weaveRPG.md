# weave RPG 团队视图｜游戏设计文档
> 文档定位：纯游戏设计层规格，覆盖玩法语义、玩家文案、像素视觉与动画参照。
> 目标读者：产品设计师、游戏美术、动效设计师、AI 生图操作者与功能开发者。
> 版本：v0.1｜状态：视觉与玩法基线｜建议画布：桌面端优先，兼容窄屏观察。
---

## 第一章 总览
本章定义 RPG 团队视图的世界观、玩家身份与核心体验边界。
**世界观一句话：你的 AI 编程团队就是一支修真/武侠门派，办公室即山门。**
### 核心体验
1. 你打开 weave，不是在看一排冷冰冰的会话窗口，而是在看一群门人各自修行、协作、出征。
2. 每个 AI 会话都有稳定的门派身份、可见的工作状态与持续成长的角色档案。
3. 你大部分时间只需旁观全局，在关键节点拍板；游戏感负责让复杂编排变得直观，不负责制造额外操作负担。
### 玩家是谁
玩家是门派掌门，也是现实中的开发者。玩家化身为全队唯一的**协调者**：站在全图视角观察队伍、分派任务、传递指令与查看战报。协调者不参与六维比较，不领取任务，也不与门人争夺镜头。

| 玩家行为 | 游戏中的感受 | 设计原则 |
|---|---|---|
| 挂机观察 | 看门人工作、休息、修炼与状态变化 | 默认信息一眼可读，不要求持续操作 |
| 偶尔拍板 | 出征、传音、批阅、调整队伍 | 关键动作明确，确认成本低 |
| 回看成果 | 查看任务战报、成长与成就 | 所有反馈都能追溯到真实事件 |
| 切换场景 | 在办公区、教室、会议室与武林大会间切换 | 同一团队，不同观察视角 |

## 第二章 角色与化身
本章解释“角色类型”和“具体会话”之间的关系，并建立七型门人的视觉识别规则。
### 角色（类）与化身（实例）
**角色（类）**是门派里的职业气质，回答“这类门人擅长什么、看起来像什么”。基础七型固定为能量、思考、创造、连接、审核、执行、适配。角色类型提供默认人设、立绘轮廓与推荐职责，不代表模型能力排名。
**化身（实例）**是某一次真实编程会话在游戏里的具体门人，回答“现在是谁在工作、拿着什么兵器、正在做哪件事”。一个角色类可以对应多个化身；每个化身都绑定自己的会话身份、模型武器、装备、技能、状态、六维展示值、等级与战绩。

| 概念 | 玩家看到的东西 | 规则 |
|---|---|---|
| 角色（类） | 七型门派职业、基础立绘模板 | 定义气质与视觉差异 |
| 化身（实例） | 有名字、有模型、有状态的具体门人 | 对应一个编程会话 |
| 协调者 | 地图上的掌门标记 | 全队唯一，不进入六维与任务分配 |
| 门人名牌 | 名称、角色型、模型品阶、等级、状态 | 优先展示识别信息，不塞满数据 |

### 基础七型人设与立绘气质

| 类型 | 一句话人设 | 体型、配色与工具 | 神态与动作气质 |
|---|---|---|---|
| 能量 | 执行攻坚，专啃最硬的骨头。 | 矮壮结实；赤橙主色；重型键盘锤或破障钻。 | 眉眼坚定、身体前倾，动作短促有力。 |
| 思考 | 深度推理，擅长把复杂问题想透。 | 修长端正；靛蓝与冷紫；卷轴、书册或悬浮符文屏。 | 眼神专注、常托下巴，动作沉稳而少。 |
| 创造 | 设计生成，把空白变成可用方案。 | 轻巧灵动；桃粉与明黄；画笔、像素尺或灵感灯。 | 眼睛明亮、略带笑意，动作有弹性。 |
| 连接 | 沟通协调，让分散门人彼此接上。 | 中等身形、披风或长围巾；青绿与湖蓝；信鸽符、耳麦。 | 亲切机敏、常侧耳倾听，动作流畅。 |
| 审核 | 审查把关，专找遗漏与隐患。 | 瘦削利落；灰白与金色；放大镜、印章或校验尺。 | 目光锐利、嘴角平直，动作克制精准。 |
| 执行 | 任务落地，把计划一步步变成结果。 | 匀称耐力型；草绿与土黄；工具腰带、扳手键盘。 | 可靠专注、微微点头，动作规律稳定。 |
| 适配 | 杂学与兜底，遇到陌生问题也能接住。 | 圆润灵活；紫罗兰与薄荷色；百宝袋、折叠工具。 | 好奇、略显机灵，动作多变但不慌乱。 |

### 化身负责模块的呈现
- **身份牌**：会话显示名、基础七型、当前等级；名称过长时截断，悬停或选中后显示全名。
- **兵器位**：模型以武器呈现。haiku → 凡铁，sonnet → 精铸，opus → 光剑；自定义模型显示为「无名凡兵」，并直显真名。
- **装备位**：已安装的插件与 MCP 作为装备图标；图标数量过多时显示前 3 件与“+N”。
- **技能位**：已安装的 skill 作为技能；修炼即安装技能。技能图标不替代真实名称。
- **状态位**：工作中 / 空闲 / 蓄力（压缩中）/ 受伤（出错）/ 离场（已结束），以姿势、色彩和微动画共同表达。
- **成长位**：XP、等级、六维与成就来自真实事件统计；不把装饰数值伪装成模型客观能力。
### 六维展示口径

| 六维 | 游戏化解释 | 建议视觉提示 |
|---|---|---|
| 力量 | 攻坚与处理重型任务的表现 | 重击符号、厚实刻度 |
| 智慧 | 推理、拆解与理解复杂上下文的表现 | 书页、眼睛符号 |
| 敏捷 | 切换任务、响应变化的表现 | 羽毛、短促速度线 |
| 速度 | 完成有效工作回合的节奏表现 | 闪电、计时刻度 |
| 内力 | 当前会话上下文占用 | 蓝紫色内力条 |
| 运气 | 偶发高效、意外发现等统计趣味项 | 星点、随机签 |

六维是团队观察用的游戏化指标，不构成模型质量、人格或能力的客观评测。数值允许调参，展示时应提供口径说明。

## 第三章 任务系统
本章把编排 run 翻译成门派任务，让玩家不必学习第二套任务逻辑。
### 四类任务

| 任务类型 | 游戏呈现 | 文案口吻 | 典型节奏 |
|---|---|---|---|
| 日常 | 小型委托牌，浅色边框 | 轻松、短促：“顺手办件小事。” | 短跑，适合小修复、问答与轻量改动 |
| 主线 | 长卷轴任务牌，带章节标记 | 明确、有推进感：“此事关系山门进度。” | 多阶段，适合功能开发与跨文件改动 |
| Boss | 大型首领令、危险纹章与进度槽 | 庄重、有压迫感：“硬仗开场，稳住阵脚。” | 长任务，适合复杂重构、疑难排障 |
| 迭代 | 带版本印记的连续任务牌 | 务实、强调改进：“再磨一轮，精益求精。” | 多轮循环，适合评审反馈与持续优化 |

难度、风险、奖励均为**任务标注**，不是第五种任务类型。建议使用三枚小标签：难度用星级或阶位，风险用盾牌颜色，奖励用铜钱/经验符号。标注不得覆盖真实任务状态。
### 任务看板像素 UI
- 看板采用 3 列或 4 列卡槽：待出征、进行中、待批阅、已归档；窄屏时改为横向分页。
- 每张任务卡尺寸基准为 112×64 px（桌面逻辑像素），边框 2 px，内边距 6 px。
- 卡片第一行显示任务类型纹章与短标题；第二行显示负责人头像、状态与进度；底部显示难度 / 风险 / 奖励小标签。
- Boss 卡宽度可扩展至普通卡的 2 倍，顶部加 8×8 像素首领纹章；禁止用大面积红色闪烁制造持续干扰。
- 任务状态以图标与文字双重表达，不只依赖颜色。超长标题最多两行，溢出以省略号处理。
- 已完成任务降低饱和度但保留可读性；失败任务显示裂纹印记，不使用血腥或惩罚性画面。
示例文案：

| 场景 | 主文案 | 辅助文案 |
|---|---|---|
| 日常开始 | “接个小委托。” | “预计片刻，办完就回。” |
| 主线推进 | “山门修缮已过半。” | “还有 2 个阶段待完成。” |
| Boss 开始 | “前方硬仗，诸位列阵。” | “高风险任务，留意战报。” |
| 迭代返工 | “再打磨一轮。” | “根据批阅意见继续精进。” |
| 任务完成 | “此役告捷！” | “战报已归档。” |

## 第四章 成长与成就
本章规定成长反馈如何映射真实工作事件，避免为了游戏化而凭空刷数值。
### XP 来源与等级
XP 只从可解释的真实事件派生，数值权重是可调占位值：

| 来源 | 玩家口径 | 建议基础 XP | 约束 |
|---|---|---:|---|
| 任务完成 | 完成一项委托，论功行赏 | 20 | 以 run 完成事件为准 |
| 有效回合 | 有实际产出的有效交锋 | 2 | 排除纯等待与重复心跳 |
| 修炼 | 安装一个 skill，习得新招 | 10 | 安装成功才计入 |
| 迭代完成 | 根据批阅意见完成一轮改进 | 额外 5 | 可与任务完成奖励叠加，需防重复结算 |

等级阈值固定采用 **100 × level²**。这里的阈值表示达到该等级所需的累计 XP：1 级 100 XP、2 级 400 XP、3 级 900 XP，以此类推。等级提升只提供成长反馈，不自动改变真实模型权限或任务能力。
### 境界文案包装

| 等级区间（建议） | 境界名 | 升级提示 |
|---|---|---|
| 1–2 | 初入山门 | “入门有成，先把基本功练稳。” |
| 3–4 | 淬体 | “筋骨渐强，可以接更重的活。” |
| 5–7 | 凝气 | “气息渐成，协作开始顺手。” |
| 8–11 | 筑基 | “根基已稳，能扛起一段主线。” |
| 12–16 | 金丹 | “自成一套，复杂任务也能从容推进。” |
| 17–22 | 元婴 | “神识外放，能在多线任务中保持节奏。” |
| 23–30 | 化神 | “洞察全局，处理棘手问题更有章法。” |
| 31+ | 登峰 | “一门绝学已成，继续精进没有止境。” |

### 成就系统
成就由事件统计派生；每条成就应有名称、触发条件、首次解锁时间与简短说明。成就只记录事实，不发明不可验证的剧情。

| 成就 | 触发口径 | 解锁文案 |
|---|---|---|
| 首杀 | 首个任务成功完成 | “第一份战报，落款已成。” |
| 满内力施法 | 会话上下文占用达到展示上限前的满格状态并成功完成一次有效回合 | “气海充盈，一击中的。” |
| 七人成军 | 同时存在 7 个活跃化身 | “七人成军，山门初具规模。” |
| 初次修炼 | 首次成功安装 skill | “习得新招，修为又进一寸。” |
| 兵器入手 | 首次识别出模型武器品阶 | “兵器认主，锋芒初现。” |
| 光剑出鞘 | 使用 opus 模型完成一次任务 | “光剑出鞘，锋芒毕露。” |
| 精铸良兵 | 使用 sonnet 模型完成一次任务 | “精铸在手，稳扎稳打。” |
| 凡铁开锋 | 使用 haiku 模型完成一次任务 | “凡铁亦可开锋。” |
| 百回合 | 累计 100 个有效回合 | “百炼成章，功夫不负有心人。” |
| 连战连捷 | 连续完成 5 个任务且中间无失败任务 | “连战连捷，士气正盛。” |
| 审阅有方 | 完成 10 次批阅战报 | “明察秋毫，守住质量关。” |
| 满门归档 | 所有已结束会话均已归档或离场 | “诸事有终，门庭清朗。” |
| 迭代匠心 | 完成 10 次迭代任务 | “反复打磨，方见真章。” |

## 第五章 像素视觉规格
本章是美术生产基线；尺寸、色值、像素边界与信息层级均按可直接制作的数字执行。
### 整体美术方向
采用 16-bit 时代的俯视角 RPG 办公室美术：清楚、温暖、略带武侠幻想，不做写实材质。角色与场景共用像素网格，轮廓优先于纹理，信息优先于装饰。

| 项目 | 规格 |
|---|---|
| 基础 sprite | 角色基础 32×32 px；小图标 16×16 px；大型标志物 32×48 px |
| 场景 tile | 16×16 px；地图以整数 tile 拼接 |
| 逻辑缩放 | 2×、3×、4×整数倍；禁止非整数缩放 |
| 角色比例 | Q 版 2.5 头身；头部约 14×12 px，身体约 10×10 px |
| 轮廓线 | 外轮廓 1 px 深色；重点装备可用 2 px 阶梯轮廓 |
| 像素采样 | `image-rendering: pixelated`；禁止双线性 / 三次插值 |
| 阴影 | 角色脚下 8×3 px 椭圆像素影，透明度阶梯化，不做模糊阴影 |
| 高光 | 每个材质最多 2 档高光，避免渐变糊边 |

### 角色立绘规格
每个角色基础画布 32×32 px，透明背景，脚底对齐 y=30；头部中心位于 x=16、y=9。每型制作正面待机、侧向工作、受伤、离场四套基础动作，装备作为独立图层，方便更换模型武器与插件装备。

### 状态映射动画帧表
帧时长以毫秒计；所有循环按整帧播放，不插值。每帧均为 32×32 px，帧间不改变角色脚底基线。

| 状态 | 帧数 | 单帧时长 | 总时长 | 动作描述 |
|---|---:|---:|---:|---|
| 工作中 | 4 | 120 ms | 480 ms | 敲键盘 4 帧循环：手落下、键帽亮、抬手、回正 |
| 空闲 | 2 | 500 ms | 1000 ms | 呼吸起伏 1 px，偶尔眨眼 |
| 蓄力（压缩中） | 4 | 160 ms | 640 ms | 周身气旋由脚边升起，逐帧收拢至头顶 |
| 受伤（出错） | 3 | 180 ms | 540 ms | 角色明暗交替闪烁；头顶叹号弹出并停留 |
| 离场（已结束） | 4 | 180 ms | 720 ms | 饱和度逐帧降低，最后一帧透明度归零 |

七型在同一状态下共用节奏，但保留动作差异：能量工作时手臂幅度 +2 px；思考工作时增加 1 帧短暂符文亮点（不增加循环总帧）；创造工作时画笔尖闪 1 px；连接工作时围巾尾端摆动 1 px；审核工作时放大镜每循环偏移 1 px；执行工作时工具腰包轻微上下 1 px；适配工作时百宝袋弹动 1 px。差异不得改变状态语义。

## 第七章 像素动画规格
本章定义状态动画、场景特效与资产交付方式；所有动画均以离散像素帧表达，不使用平滑补间。
### 状态→动画映射总表

| 状态 | 通用帧数 / 单帧时长 | 循环 | 七型差异点 |
|---|---|---|---|
| 工作中 | 4 帧 × 120 ms | 是，480 ms 一轮 | 能量大幅敲击；思考符文点亮；创造笔尖闪光；连接围巾摆动；审核镜片偏移；执行工具包轻跳；适配百宝袋弹动 |
| 空闲 | 2 帧 × 500 ms | 是，1000 ms 一轮 | 能量双臂放松；思考眨眼；创造轻晃画笔；连接侧耳；审核抬镜；执行点头；适配摸袋口 |
| 蓄力（压缩中） | 4 帧 × 160 ms | 是，640 ms 一轮 | 能量气旋偏红；思考气旋呈符文环；创造气旋带星点；连接气旋连成双线；审核气旋为方框；执行气旋稳定上升；适配气旋不规则但闭合 |
| 受伤（出错） | 3 帧 × 180 ms | 否；错误持续时每 1800 ms 重播一次 | 能量锤落地；思考卷轴合起；创造画笔下垂；连接围巾停摆；审核镜片裂纹符号；执行工具包掉落 1 px；适配百宝袋倒扣 |
| 离场（已结束） | 4 帧 × 180 ms | 否 | 七型统一灰化；各自标志物保留轮廓，最后一帧淡出 |

状态优先级：离场高于受伤，受伤高于蓄力，蓄力高于工作中，空闲为默认。若真实状态改变，动画从当前状态切换到新状态的第 1 帧，不做交叉淡化。
### 特效清单

| 特效 | 画布 / 帧数 | 节奏 | 像素表现与触发 |
|---|---|---|---|
| 升级光环 | 48×48 px / 6 帧 | 90 ms / 帧，播放 1 次 | 金色阶梯圆环由脚边扩至头顶；等级提升时触发 |
| 修炼特效 | 32×32 px / 4 帧 | 140 ms / 帧，循环 2 次 | 技能书翻页；每页翻动 1–2 px，最后出现 8×8 符文 |
| 任务完成撒花 | 64×48 px / 8 帧 | 80 ms / 帧，播放 1 次 | 纸花、星点从卡片上沿向两侧散开；不遮住标题 |
| 受伤飘字 | 32×16 px / 6 帧 | 100 ms / 帧，播放 1 次 | “出错”或错误短标签上浮 8 px；随后停留为可读标记 |
| 传音飞线 | 连接两角色的动态画布 / 6 帧 | 70 ms / 帧，播放 1 次 | A 到 B 的像素弧线分段点亮，末端出现 8×8 飞符 |
| 大屏刷新扫描线 | 屏幕内容区宽度 × 2 px / 4 帧 | 90 ms / 帧，按需播放 | 1 px 亮线逐行移动，经过区域短暂提亮 1 档 |

特效节制规则：同一角色同一时刻最多显示 1 个角色特效；全场同时播放的高亮特效最多 3 个。任务完成撒花优先级高于普通提示，扫描线不得遮挡关键文字。
### 帧动画实现约定
- Sprite sheet 按“每行一个动作、每格同尺寸”组织；角色动作每格 32×32 px，特效按表中画布尺寸独立输出。
- CSS 动画使用 `@keyframes` 配合 `steps(N)`；帧数为 N 时，步进必须是 `steps(N)`，不得使用 ease、linear 插值模拟像素帧。
- 横向 sprite sheet 的背景定位按单帧宽度整数倍移动；动画总宽度必须等于单帧宽度 × 帧数。
- 所有像素图使用 `image-rendering: pixelated`；显示尺寸只允许源尺寸的整数倍。
- 禁止 blur、drop-shadow 模糊、渐变透明过渡与连续 transform 插值；需要淡出时使用预制离散帧或阶梯透明度。
- 状态切换采用硬切到新动作第 1 帧；允许 1 帧静止作为视觉缓冲，但不得额外增加等待。
- 动画暂停或系统降帧时，优先保留状态正确性；装饰性粒子可以停，状态图标与文字不能停。
- 色盲与低亮度环境下，状态仍须由文字 / 形状 / 姿势辨认，不得只靠颜色区分。

## 第八章 不做什么
本章划定游戏化边界，避免视觉包装反过来改变 weave 的真实工作方式。
- **不做对战模拟**：武林大会只展示六维雷达对决、排行榜与兵器谱，不计算虚构伤害、不模拟 PvP、不让角色互相攻击。
- **不做第二任务引擎**：任务仍然来自编排 run；日常、主线、Boss、迭代只是展示分类，不复制一套任务生命周期。
- **不做游戏内写操作**：RPG 视图不提供独立代码编辑、文件修改或与真实会话脱节的操作入口；游戏动词只包装既有动作。
- **数值全为占位可调**：六维、XP 权重、等级反馈、难度 / 风险 / 奖励标注均可调；不得将装饰数值宣称为客观模型测评。
- 不做角色死亡、永久损失、惩罚性掉级或影响真实任务结果的随机事件。
- 不把空闲解释为失败，不把受伤解释为真实损害；状态必须忠实映射会话事实。
- 不用高频闪烁、强对比呼吸灯或持续音效打扰开发者。
- 不让协调者参与门人排名，不给协调者分配 run，也不把协调者拆成多个实例。
