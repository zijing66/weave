weave RPG 世界视图 — 前端视觉还原与双端适配开发指令
一、你的任务
你是一名资深游戏 UI 工程师、像素美术设计师和前端开发工程师。
请根据我提供的两张参考图片：
- 参考图 A：PC 横屏游戏世界视图（16:10）
- 参考图 B：手机竖屏游戏世界视图（9:19.5）
对 weave 的「RPG 团队视图
/ 上帝视角世界」进行完整的前端视觉还原。
这不是普通后台管理系统，也不是一个游戏主题的 Dashboard，而是一个真正具有红白机（FC/NES）俯瞰式 RPG 游戏体验的 Web 游戏界面。
核心目标：最大程度还原参考图的构图、像素美术、空间比例、色彩、HUD 布局和视觉细节，同时实现真正可运行的响应式前端。
不要直接将参考图片作为网页背景或整张图片展示。必须将地图、房屋、角色、状态条、HUD、属性栏、控制按钮拆解为独立的前端元素。
---
二、整体视觉定位
主题：上帝视角的 AI Agent 协同修仙世界。
美术风格：
- FC
/ NES 时代的 16-bit 俯瞰式像素 RPG。
- Stardew Valley 的温暖自然色彩。
- RimWorld 的高信息密度游戏 HUD。
- 结合东方修仙世界的建筑、灵田、修炼点等元素。
- 整体低饱和、暗色基底、沉浸式游戏氛围。
视觉关键词：
Retro Pixel Art、Top-down RPG、God View、AI Agent Simulation、Dark Fantasy、Pixel HUD、Cozy Strategy Game。
禁止：
- 现代 SaaS Dashboard 风格。
- 蓝紫色科技渐变。
- 大面积玻璃拟态。
- 现代 3D 游戏渲染。
- 真实摄影素材。
- 圆润卡片式后台布局。
- 过度艳丽的游戏 UI。
整个世界应该像一台深夜运行的复古游戏机。

三、技术实现要求
首先检查当前项目的技术栈、目录结构和现有组件。
优先沿用项目已经使用的技术和规范，不要擅自重建项目或覆盖已有功能。
如果项目尚未建立前端框架，默认使用：
- React
- TypeScript
- Vite
- CSS Modules 或项目现有 CSS 方案
实现方式：
1. 游戏地图使用 HTML Canvas 或独立的像素地图渲染层。
2. HUD 使用 HTML + CSS 构建，保证文字清晰。
3. 地图中的房屋、树木、石头、灵田、角色使用独立像素精灵。
4. 所有角色和场景元素使用像素化渲染。
5. 游戏 UI 与地图渲染层分离。
6. PC 与移动端共享同一份世界数据和游戏状态。
7. 使用响应式布局，而不是简单地对 PC 页面进行整体缩小。
地图绘制应支持：
- Tile 网格。
- 图层叠加。
- 地图元素定位。
- 角色坐标。
- 角色状态条。
- 选中角色高亮。
- 镜头视口裁切。
如果没有现成素材，可以通过 Canvas、CSS 像素绘制或自制 SVG 像素素材构建，不要依赖在线图片资源。

4.2 世界地图
地图使用俯瞰式正交视角。
基础网格：
- Tile 尺寸建议 24×24px。
- 草地使用深绿色和墨绿色交替棋盘格。
- 保持像素块边界清晰。
- 不使用模糊纹理。
- 不使用渐变地面。
场景元素：
草地
- Moss Green：#243d2b
- Jade Green：#315238
- Dark Grass：#192c22
主路
- 横向贯穿地图。
- 土黄色、沙色、亚麻色。
- 具有轻微颗粒纹理。
- 路边存在不规则草丛。
项目房
- 4～6 座小屋。
- 每座房屋占据 2×2 Tile。
- 木制墙体。
- 暖橙色瓦片屋顶。
- 深色门窗。
- 每座房屋有独立阴影像素块。
- 建筑排列沿着主路展开。
宅基地
- 位于主路一端。
- 浅灰色石板地面。
- 中间有东方符文图案。
- 两侧可以有石灯。
灵田
- 位于地图另一侧。
- 2×2 格子。
- 棕色耕地。
- 几株嫩绿色幼苗。
- 周围有青绿色灵气粒子。
- 灵田具有低亮度的青色发光效果。
自然环境
- 松树、灌木、花草、岩石。
- 地图上方或右侧可以有湖泊。
- 湖泊使用深蓝色像素水面。
- 岸边使用石块装饰。
- 地图下方分布树木和石头。
地图要具有丰富的细节，但不能喧宾夺主。
4.3 AI Agent 角色
地图中出现 3～5 个 Q 版像素角色。
角色使用 16×16 或 24×24 的基础精灵风格。
视觉特点：
- 大脑袋。
- 小比例躯干。
- 两格腿。
- 清晰的色块服装。
- 东方修仙人物装束。
- 每个角色具有不同的发型和服装颜色。
其中一个角色是「上帝化身」：
- 白色素衣。
- 深色头发。
- 站在主路中央。
- 具有轻微青色选中标记。
- 不要比其他角色大。
- 头顶显示绿色状态条。
其他 Agent 使用蓝色、棕色、紫色等服装。
每个角色头顶显示：
- 绿色：正常。
- 黄色：警告。
- 红色：异常。
状态条高度 2～3px，不显示大数字。
角色支持：
- 待机动画。
- 行走动画。
- 工作动画。
- 修炼动画。
- 异常状态动画。
动画使用像素帧切换，不要使用平滑 3D 动画。

这是独立设计的移动端游戏布局，不是 PC 页面缩小版。
6.1 整体布局
移动端比例：9:19.5。
采用纵向布局：
- 上方约 80%：游戏世界。

6.2 世界地图
地图在移动端采用独立的纵向镜头布局。

不能直接把 PC 地图压缩成手机宽度。
需要重新组织地图的空间构图：
- 上方为森林、湖泊。
- 中间排列项目房。
- 中部为横向土路。
- 路上分布 Agent 角色。
- 一侧为灵田。
- 另一侧为宅基地或修炼点。
- 下方为森林和自然景观。
角色始终保持清晰可见。
通过镜头缩放和视口裁切，保证地图的主要场景都能在手机屏幕上呈现。

左上角：
小型徽章：
「游戏视图 · World · 返回」
右上角：

尽量精简，不占用太多地图空间。
统一控制台可以收纳为小型按钮或折叠入口。
异常警报可以缩小为紧凑标签，不允许遮挡主要角色。
6.4 移动端角色详情
移动端不能照搬 PC 底部的大型属性 HUD。
使用紧凑的横向详情条，放置在世界地图底部边缘。
展示：
- 角色头像。
- 上帝化身。
- 运行中。
- 修为 Lv.3。
- 简化版六维属性。
- 最近回合摘要入口。
允许将详细属性和回合摘要折叠或通过点击展开。
6.5 底部实体控制带
这是移动端最重要的独立区域。
占据屏幕底部约 20%。
使用深色不透明背景：
#17141f
顶部增加一条细灰色分隔线。
中央放置十字方向键：
- 上。
- 下。
- 左。
- 右。
每个按键约 52×52px。
按钮样式：
- 方形圆角。
- 深灰紫色背景。
- 细灰色描边。
- 中间白灰色方向箭头。
- 按下时背景变亮青色。
- 像素化边缘。
- 禁止现代手机游戏的高光渐变。
布局示意：
          [ ↑ ]
    [ ← ]       [ → ]
          [ ↓ ]
四个按钮必须能够实际触发角色移动。
支持：
- 点击移动。
- 长按连续移动。
- 触控反馈。
- 方向键与键盘 WASD 同步。
控制带必须始终处于屏幕底部，不能被浏览器安全区域遮挡。

七、双端统一交互
PC 和移动端必须共用一套游戏状态。
至少实现以下交互：
1. 点击地图中的 Agent，可以选中角色。
2. 选中后，角色出现青色选中标记。
3. 底部详情 HUD 随角色切换。
4. 角色头顶状态条实时显示。
5. 方向键能够移动当前角色。
6. WASD 能够在 PC 端控制角色。
7. 点击项目房可以查看项目详情。
8. 点击灵田可以查看灵田状态。
9. 点击宅基地可以查看基地信息。
10. 点击统一控制台可以打开控制台入口。
11. 警报标签支持查看待处理事件。
12. 最近回合摘要可以切换查看历史记录。
如果当前项目尚无后端数据：
使用 Mock 数据实现交互。
不要伪造已经连接真实 AI Agent 的能力。
所有演示交互必须有明确的视觉反馈。
