## 二、并入既有版图：全景大表

既有竞品版图（Vibe Kanban、Conductor、Sculptor、Claude Squad、crystl、Superset、Pane、Paperclip、
Codeg 的定位见 [`weave定位与竞品分析.md`](./weave定位与竞品分析.md)）。四新竞品并入后，**接线方式**
这个轴上出现了清晰的四象：

| 接线哲学 | 代表 | 本质 | 与 weave 的关系 |
|---|---|---|---|
| **装进自己的壳** | Codeg、lody（ACP）；t3code（RPC+PTY） | spawn 子进程、结构化流，全面接管 | 替代用户环境；weave 的 provision 槽同族但 weave 不搬家 |
| **终端共生** | orca（复用已有 pane）；Codeg 反面 | 寄生用户已有终端 | **与 weave 同地层**，见 §三 |
| **读屏 + 开放协议** | herdr | 不改 agent、看屏幕猜状态；OSC 7501 让 agent 自愿上报 | 比 hook 采集粗一档，但零改造成本 |
| **worktree 任务卡** | Vibe Kanban、Conductor、Sculptor、lody | 任务 → 分支 → diff 审批 → merge | 任务管理层，weave 的诚实短板区 |

**关键观察：竞品又新增了两个「weave 没有的东西」的正名**——

1. **移动端已成标配**：四家里四家都有原生移动 App（herdr 手机作答含贴图/语音、t3code Live
   Activity、lody Dynamic Island 进度+权限弹框）。weave 的「局域网 HTTPS + Web Push」从「差异化
   亮点」降级为「及格线」。见 §四-2。
2. **checkpoint / 回滚成为新共识**：t3code 用 hidden git ref 做 turn 级工作区快照与回滚、lody
   每 turn 落 diff 可回溯。weave 有 rewind 槽（转录回退）但没有工作区 checkpoint——两者正交，
   但「回到这轮之前」的心智已被市场教育出来了。见 §四-3。

## 三、按 weave 的差异化护城河逐条对照（四新竞品视角）

既有定位稿的六条护城河（会话活性 / 跨会话通信 / 终端共生 / 多 harness 能力面 / 生产消费解耦 /
本地优先+手机），用四新竞品重测：

1. **会话是活的生物** —— herdr 的双通道判活（读屏 manifest + OSC 7501）是四家里最接近这个理念
   的，甚至 OSC 让「agent 自愿上报状态」成了开放标准。但它的状态只有 idle/working/blocked
   三态粗粒度，没有事件链 / 回放 / 投递语义。**护城河仍在，但 herdr 证明了「状态采集」这个
   方向的独立市场价值。**
2. **跨会话通信是真实基建** —— 四家全部没有。herdr 的 `hc send` / `run --bg` 是人与 agent 的
   通道 + agent 间报告回注，最接近但无回执/闸/投递可靠性语义；t3code delegated task 是父子
   委派非自由通信；lody 交给主 agent 用 MCP 工具自律巡检。**weave 的三层投递 + 1送1回执 + 闸
   依旧独一份。**
3. **终端共生** —— orca 直接撞这条：它也复用已有终端 pane（检测白名单 agent）。差异在深度：
   orca 的 pane 分类靠 CLI 白名单（新 agent 不可见，issue #9414），weave 是 locator env 精确
   定位 + 标题回落 + 击键逐字节工程（Kitty 协议、INPUT_RECORD stride）。**方向被验证，深度
   仍领先；白名单方式正是反面教材（呼应 Codeg 744 处硬编码的教训）。**
4. **多 harness 能力面** —— lody 走 ACP 宽度（40+ 一套协议），weave 走深度（二十一槽）；herdr
   25+ 但深度靠 per-agent integration 配置文件改写（与 cc-switch 整写 config.toml 同类风险）。
   **既有「窄而深 vs 广而浅」的判断继续成立，且 ACP 阵营又添一家。**
5. **生产消费解耦 / 生命周期可靠性** —— t3code 是新标杆：event-sourcing（命令→事件→投影→
   outbox）+ 幂等回执 + 丢失 provider 副作用 retire 不盲重放 + daemon 重启恢复。与 weave 的
   hook 零活依赖 + rearm 最小续跑是同等级的工程投入，甚至部分超我们。「竞品不靠谱」这个
   心理优势对 t3code 不成立。**
6. **本地优先** —— 唯一护城河被正面攻破：herdr SSH/Tailscale 直连**免云账号、不经服务端**，
   比 weave 的「本地 + 局域网」更广（跨网段远程）。lody 反向连云不算本地优先负面对照；
   t3code 的 T3 Connect 有中继成分。**weave 的联邦规划（mDNS + pairing）需要对标 herdr 的
   SSH 直连形态——「免账号直连」值得直接借鉴为联邦的传输层选项。**

## 四、功能取舍与借鉴清单（按 ROI 排序）

### 1. 立即可抄的工程细节（天级，不动架构）

| # | 借鉴点 | 来源 | 落点 |
|---|---|---|---|
| a | **OSC 7501 开放状态协议**：一行 printf 让任意 agent 自愿上报状态，与读屏判活互补 | herdr | capture 槽的第三通道候选：hook 事件账之外，agent 侧无配置可装（比 codex hooks trust 闸还轻）。排后热议，先观察生态采纳度 |
| b | **用量面板字段面**：token / 缓存命中率 / 按模型拆分 / 订阅加价估算 | t3code / lody | B4 成本面（已在路上）的字段清单参照，避免只做 token 数不做成本折算 |
| c | **PR 合并自动归档/settle**：merge 落地会话自动收尾 | lody / t3code | B5 worktree + review 批阅闭环的尾部环节，落 weave = 编排图的「PR 事件 → 收尾」边 |
| d | **checkpoint = hidden git ref**：turn 级工作区快照、回滚前验证会话回得去 | t3code | 与 rewind 槽正交：rewind 管转录、checkpoint 管文件。建议与 B5 worktree 同期（worktree 内做 checkpoint 无碍共享区） |

### 2. 中期取舍判断（需要决议，非默认做）

| 议题 | 争论 | 建议 |
|---|---|---|
| **原生移动 App** | 四家全有原生 App；weave 是 web。做原生 = 双端维护成本 + 现有 web 移动适配作废一半 | **不做原生，补差距件**：iOS 的 Web Push 已可达（WNS 实测通）；补「锁屏实时进度」等价物 = SSE + Web Push 已能拼；Dynamic Island 级别的常驻展示不做（PWA 无此通道，等 PWA Layer 3 通用化再说） |
| **SSH/Tailscale 直连** | herdr 证明「免云跨网远程」有真实需求；weave 联邦原计划 mDNS + pairing | **联邦传输层直接考虑 SSH 隧道形态**：mDNS 只管发现，跨网段走用户自己的 Tailscale/SSH 隧道最省事——weave 不自建中继（t3code T3 Connect 的中继是云依赖，反面）。联邦设计稿加一节「经由用户自建隧道的 peer 接入」 |
| **agent 自决编排（MCP 工具）** | lody Agent Session Control / Codeg delegate_to_agent：agent 用工具创建/巡检别的会话 | 原定位稿已记（Codeg 可借鉴②）。**维持原判**：作为 MVP 面已有工具的补充（triggerManualOrchestration 之类），不重做编排引擎；图驱动与 agent 自决正交并存 |
| **steer / 插话到运行中回合** | ACP `session/steering` 三态回执被 Codeg/lody 采用 | weave 已有对应答案 = 层② mid-turn 投递 + 人在场闸 defer（CLI guide 域实测），语义还更细。**无需动作**，可在 docs 里把对照写明 |

### 3. 竞品威胁重排（更新定位稿§一的「正面重叠最大」结论）

- **正面重叠最大仍是 Codeg**（全功能工作台）+ **新晋 t3code**（工程质量 + 移动端 + 远程委派，
  55k★ 增速意味着它可能成为「多 harness 编排」心智占有者）。
- **herdr 是理念最近的对手**（runtime/判活/多机/移动全撞），但编排深度（无 DAG）与插件依赖
  结构使它在 weave 的强区是浅的。跟踪观察：若 herdr 插件生态长出图编排 + 回执投递，威胁升
  级。
- **orca 与 weave 同走终端共生**，是「终端共生」路线的第一次外部验证；深度差距在 pane 白名
  单 vs locator env。
- **lody 走团队协作 + 云依赖**，方向不同（团队共享活会话、按成员计费），中短期内不构成个体
  本地场景的直接竞品，但其「会话共享给同事（只读）」的能力 weave 完全没有——团队场景出现
  真实需求前不追。

### 4. weave 短板清单更新（对照定位稿§三诚实短板表）

原五条短板（worktree / review 闭环 / 任务语义 / 成本面 / 沙箱）**全部仍然成立**，且四新竞品
家家都有 worktree 隔离——这条从「竞品标配」升级为「赛道地板」。另新增：

- **移动端实时性**：从「亮点」降为「及格线」，见 §四-2。
- **checkpoint/回滚**：t3code/lody 已把「turn 级时间旅行」教育成市场预期，worktree 落地时同
  期带上（§四-1d）。

## 五、结论（一段话）

四新竞品全是**任务管理层 + 装进自己的壳**（或轻度共生）的路线，没有一家同时做到
「终端共生 + hook 级事件账 + 图编排引擎 + 投递可靠性」——weave 的地层定位经第二轮对标依然
成立。变化的是**及格线**：移动端、worktree、成本面板、checkpoint 已是标配；以及**新的最强
单点对手**：t3code 工程品质、herdr 理念重合。应对不变：守住会话运行时 + 图编排 + 终端共生，
按 §四清单吸收工程细节（b/c/d 三条直接进 backlog），并跟踪 herdr 插件生态与 ACP 采纳度两个
先行指标。
