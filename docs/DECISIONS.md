CLAUDE.md 只保留当前站立规则；带日期的定案、实测记录、用户原话裁决与被推翻的旧结论一律记录在这里。append-only，新的在上。

## 2026-10-16

- **压缩态的信号选型（反编译 claude 2.1.296 实测；起因 = 用户问「生成中… 字样，是否能够获取 比如压缩会话的字样？… 注意抽象实现」，并指出会话 300772bd 压缩过一次）**：`PreCompact` / `PostCompact` 是**真 hook 事件**（事件名表里确有二者），matcher 匹配的字段 = 载荷的 `trigger`（`manual`/`auto`），而 weave 生成组写的是 `{matcher:'*'}`（`matcherIsMatchAll` 视同全匹配）⇒ 组会 fire。输入形状：PreCompact = `{trigger, custom_instructions}`；PostCompact 同形另带 `compact_summary`（有一条路径以 `""` 调用）。实测串 = **PreCompact → 摘要 → PostCompact → `SessionStart(source='compact')`**；**压缩期间宿主一个 hook 事件都不发**——这正是「实时态必须压在回合逻辑之前」的原因（走 turnOpen/静默窗会把这段静默读成运行中/打开）。落地选择：**只登记 `PreCompact`**（进 `HARNESS_EVENTS.claude` + 新的可裁剪采集开关 `hooks.preCompact`）——收尾笔 `SessionStart` 早就在采集面里，故事件链那一笔的「压缩会话」tag 对存量会话**即时可见**，而实时「压缩中」须重跑 `weave init` 才亮。**不采 PostCompact**：它的唯一增量是 bulk 的 `compact_summary`，实时态与事件链标记都不需要（不做「把整份摘要塞进 `hook_events`」这种存储扩张）。抽象落点 = core `HARNESS_COMPACTION`（`start` / `end` + `endSource`，全 null = 该 harness 无压缩概念）→ web 经 `tasks/lifecycle.ts` 镜像 + 纯判据 `isCompactionEnd` → 状态机第六态 `compacting`（自带 10min 超窗，防会话被杀在压缩中永久卡「压缩中」）；「会话忙」判据收敛为 `isSessionBusy`（running ‖ compacting——组头徽标/画布动效/状态图标/项目行计数四处原先各自写 `=== 'running'`）。codex 待调研（表里空值占位）。
- **`web/tsconfig.json` 的 core 别名多了一层（顺手修正）**：原写 `../../../weave-core/src/*`，从 `packages/weave-server/web` 上溯三层 = weave 根（`packages/weave-core` 才是对的）⇒ 别名从未命中，web 的 tsc 实际解析到 `weave-core/dist/*.d.ts`，即**一直在查陈旧的 dist 类型而非源码**，与 vite alias（`../../`，源码直引）和 CLAUDE.md 的说法都不一致（core 新增导出后 web tsc 会报 `has no exported member`，须先 build core 掩盖）。已改为 `../../`。

- **宿主预览式问答面的真形（反编译 claude 2.1.296 实测，起因 = 用户报某会话出现了新提问形态）**：用户原话「左侧是选项，右侧是 字符表示的 预览，然后按n可以补充notes，然后没有 3 type something选项」。反编译 `claude.exe` 的选答器得**形态判据** `!multiSelect && options.some(o => o.preview !== undefined) && !nt()` ⇒ 预览形态**只在单选 + 任一选项带 preview** 时出现（多选即使带预览也落回旧形态），**无 Other 行**。键语义与旧形态**不同**：数字键 `1..9` **只挪高亮**（`wo(ys)`），移动过才置 `moved` 标记；`return` 才提交高亮项（`Ne(uo, value)`，默认 `shouldAdvance=true` ⇒ **提交即推进 tab，无需再补 Tab**）；`n` 聚焦备注输入；末项 ↓ 进 chat 模式（`return` = 结束整 call）；`escape` 取消。备注提交分支 `if(text.trim() && moved) 提交高亮项; else if(其它输入) …; else if(text.trim()) 提交 "(notes only)"`——即**备注只挂在「挪动过高亮」的选项上**，没挪过就只填备注则整问的答案字面量是 `(notes only)`；**空备注 + 未挪高亮 = 死局**（什么都不发生，会话继续挂着）。右栏预览归一化：`preview` 缺省 = 该选项无预览（不算进形态判据）、长度 > 2000 字符或含不可见/双向字符 →  withhold 文案「(preview cannot be shown in full — compare the option labels and descriptions instead)」、无可见内容 → 「No preview available」；左栏行 = `›` 高亮 / `N.` / 标签 / `✓` 选中，**描述在这一形态里不渲染**；`nt()`（判据里的那个否项）定义在 bundle 非连续 chunk 里**未能定位**，其唯一另一处用途是按「屏幕阅读器模式」渲染 `answered ` 文案替代复选框字形 ⇒ **推断为无障碍模式（正常为 false）**，未证实。对齐落地（10f1e10 harness/server + 8ba2456 web）：face 出 `previewMode` + 每选项 `preview` 原文 + `commit` 键序（`keys` 只挪高亮、提交另需一记回车）；因「备注只挂挪过高亮的项」，选项行 `keys` = **两键**（先挪到目标再落 1..n，单词问退化成一键）；**单词问不出备注行**（宿主结构上没有挂载点）；备注只填不选选项也合法（照宿主答成 `(notes only)`，服务端那条「选了输入行必须有文本」的闸反过来挡住空备注死局）；web 弹窗按形态换面（左选项 | 右预览 + `Notes:` 行 + 不编号的「Chat about this」，无收尾屏时底部发送键提交、表单形态走收尾屏）。
- **问答弹窗尺寸按形态各记一份（用户要求「可以视不同情况，灵活调整大小」）**：预览形态天生要宽（左选项 + 右栏原文）而旧形态 448 就够，故缺省按形态分（plain 448 宽/高度随内容，preview 880×560），桌面右下角拖角调整、`localStorage` 按形态各存一份（`weave:answer-size:<mode>`）；上限 = 外层 `p-4` 之内（`max-h-[calc(100dvh_-_2rem)]` 与 `clampSize` 同源，否则拖出来的值被裁掉）。`<lg` **整屏单列、不出现拖角**（触屏没有拖窗口这回事），预览左右分栏在窄屏塌成上下堆叠。

- **「终端」的计数/分块单位 = 一块可见屏幕（用户澄清原话）**：需求原文「给每个 terminal 限制最多 6 个 pane，再新增就只能新开 terminal 了，再给会话列表增加窗口管理的分块，一个终端的放在一个块中」；澄清原话「指的是终端的一个 tab，注意不同的终端定义不一样，总结就是每个可见的一个屏幕中，最多 6 个 pane（不支持分屏的终端不做限制，直接开新窗口）」。⇒ 上限与分块**都以「一块可见屏幕」为单位**（wezterm = 一个 tab），且这个单位的定义归各后端：不支持分屏的后端（Terminal.app / 纯 shell preset）没有「挤在同一块屏里」这回事，不设限、每个会话各占一个窗口/tab，`AttachTarget.full` 恒 false。上限实现三处（几何规则 `planWeztermGrid`、复用挑选 `pickWeztermTab` 满的 tab 跳过 → 自然落到新窗口、定点附加 `runInWeztermAt` 对已满目标明确拒绝而非擅自换地方）。**曾被考虑的替代口径**：「每个终端窗口最多 6 个 pane」——被澄清否掉（窗口可含多 tab，tab 才是用户眼里的那块屏）。
- **会话列表分块的数据面走既有隐藏刷新器，不新开探测**：会话 → 所在屏幕需要「pane env × 活 mux 表」，前者早在内存（`MessageDeliverer.paneEnvs` 旁路上报，daemon 重启即空），后者 = 会话终端定位本就在跑的 `wezterm cli list` 探活。故把 `TerminalCountsRefresher` 拓宽为 `TerminalTopologyRefresher`（快照 = `{counts, terminals}`、帧键 `terminalCounts → terminalTopology`），`GET /sessions` 回它的**上次快照**（探测吃子进程，绝不上请求关键路径），增量经 push 帧补丁行——与项目卡终端角标同一口径（`sessionLiveness` / `inflightCounts` 先例）。`locateScreens` 吃 10s 探活缓存（分组滞后十秒无感），与定位投递路径的实时枚举分开：**投递必须看实时世界**（缓存会让消息落进刚关的 pane），**展示可以吃缓存**。**块头只在同屏 ≥2 个会话时出现**——一块屏只有一个会话时那行没跟人挤在一起，立块头只是噪音；反查不到所在屏幕的行不分组、原位留在块外（不猜它属于哪个终端）。

## 2026-10-15

- **全局总览行序 = 纯活动序（用户裁决，推翻 f8aa6ea 的分桶）**：需求「给全局的任务列表，也增加项目会话相似的前端的任务排序功能」——f8aa6ea 当初落的是「活动序 + 按项目分桶（同项目相邻）」，代价是**同项目的旧会话会被压在新会话之上**。就此问过一次，用户选了「改成纯活动序（跨项目混排）」⇒ `globalOverviewRows` 退化为「按冻结序逐行取行」：冻结序里未见的新行按新在前兜底置顶、已消失的即时移除，与会话列表 `mergeNewRows` 同口径；过滤换批仍立即采用新序、不做增量合并。项目名改为行内一列承载（不再靠分组表达归属）。

- **对话视图 = 只查事件流，绝不落库**（用户裁决，本机实测）：需求「消息线程按钮改名对话；对话中仅展示用户的消息投递 + 会话 stop 时的最终总结消息」，随后两条追加「消息不落 db 库，而是查询消息」「避免冗余存储」⇒ 对话**不新增表、不复制行**，直接查既有 `hook_events`：开轮取 `UserPromptSubmit` 的 `raw.prompt`（`<task-notification>` 子代理返回不算人话，同分组口径丢），闭轮取 `Stop` 的 `raw.last_assistant_message`。覆盖实测（当机库）：最近 400 条 Stop/SubagentStop **100% 带非空 `last_assistant_message`**（均值 3.1k 字符、最长 33k），UPS 400 条里 354 条真 prompt / 46 条 task-notification / 0 条空 ⇒ 无需解析转录、无需新 API 语义。分页 = 既有会话事件路由加 `types` 参数（只取开/闭轮两类，一页 10 条事件而不是 300 条混合事件）+ `beforeId` 游标；已翻页留前端（组件状态，不开模块级缓存——重开时新页与手上不重叠就整批换新，避免留下看不见的空档）。**退场的旧做法**：web 侧那份 60s 本地隐藏（`SETTLED_VISIBLE_MS` + 一次性重渲染）删除——对话**不清理**消息；投递行改为「被同文案相邻时刻的事件条目认领即不单列」，认领不到的（Held/Refused、failed/timeout、暂停闸成因、仍在途）排对话尾部，可见期沿用服务端驻留窗口（settled 60s、failed/timeout/stalled 常驻）。对话可见历史的下界 = 事件保留期。

- **停止按钮报「找不到 pane」的真因（本机实测 2026-10-15 21:10）**：中断路径本身没问题——用**哑 pane** 端到端验证过：`wezterm cli spawn` 起一只 `node` raw 读 stdin 的 pane、把它的标题设成某历史会话标题（`✳ <session-title>`）、cwd = 该项目根 → `POST /sessions/<那个会话>/interrupt` 返回 200，且该 pane 收到**且只收到** `hex=1b`（一记 ESC）；随后 kill-pane 收摊。断言的是：`interrupt` 与 `answer` 同用 `sessionKeysTarget` → `terminalPaneFor`，键序投递这段无缺陷。409 的真因在**解析**：① 项目侧 `.claude/helpers/hook-handler.cjs` 生成于 locator 特性（5cec73e）之前 → 行形里根本没有 `terminal` 字段（本机 <project> / <project> / avic / <project> / <project> 五处 `grep -c WEZTERM_PANE` = 0，行形 = `{v,token,report,messaging}`）→ `paneEnvs` 永不落项；② 只剩「标题剥 spinner + 项目根 cwd 等值」回落，而 `--resume` 起的会话 TUI 标题回到 claude 默认「✳ Claude Code」、无题会话（`title` null，函数里直接 return null）→ 必然 0 命中。全量体检（复刻回落判据 × 当机活 pane）：weave 项目有题会话命中（0d05efc9→9394666d:9 / 300772bd→:1 / 3de0d761→:6），无题会话与其余项目大多 0 命中。⇒ 这不是停止按钮的实现问题，是**那条通道的覆盖问题**：helpers 属 init artefact、服务端同步面刻意不含它，正解 = user 档采集（`PUT /capture {harness:'claude',enabled:true}`：写一份含 locator 的 user 级脚本 + 清掉各注册项目的采集组；**只对新起会话生效**——已跑进程的 hooks 在启动时读定），或对目标项目重跑 `weave init`（脚本路径不变，进行中的会话下一次 hook 事件即生效）。同批两处小修：停止按钮与同排复制按钮的按钮形对齐会话列表（`h-5 w-5` 方框 + 边框底色，原先只有 `p-0.5` 内边距）；`TerminalBackend.sendKeys` 的 wezterm 报错文案原本写「cannot send **answer** keys」，而这条通道中断也在用 → 改中性说法。

- **同一个 409 的第三种成因：daemon 重启把内存 locator 清空（本机实测 2026-10-15 21:50）**：`paneEnvs` 只是内存 Map（`message-deliverer.ts:231`；`forgetSession` 清），daemon 一重启即空，而会话要等**下一次任意 hook 事件**才会把旁路的 `terminal` env 再报一遍 → 落在空窗里的会话停止/作答一律 409。实测：会话 `24d9da09`（`--resume` 起、入库 `title` null，宿主 pane 32「✳ Claude Code」）在 daemon（21:00 重启）之后静默一小时（20:38:40 最后一次 Stop 后无事件），按停止报 409；21:39:45 一条 UserPromptSubmit 重新上报后再调 `POST /sessions/<id>/interrupt` → **200**（无题会话只能走 locator，故这同时证明上报与 locator 都通）。旁路线确实带该字段：实时抓 `%APPDATA%/weave/hooks/inbox/*.jsonl` 得 `terminal={"WEZTERM_PANE":"1","WEZTERM_UNIX_SOCKET":"…gui-sock-28500"}`。⇒ 不是投递缺陷、也不建议为此落库（重启后旧 pane 号可能已换主，存在性校验挡不住误注入）；重启后一直没动的会话先**发条消息**（触发 hook 即上报）再停。
- **API 报错可观测性实测（本机）**：报错**只落转录 JSONL**，hook 域没有这个信号——`{"type":"assistant","isApiErrorMessage":true,"error":"server_error|invalid_request|unknown","apiErrorStatus":400|402|500,"message":{"model":"<synthetic>", usage 全 0}}`，紧邻一条 `{"type":"system","subtype":"turn_duration"}` = **该 turn 已结束**（之后是人补一句「继续」）。反证：全库 `notification_type` 只观测到 `idle_prompt`(359)/`permission_prompt`(95)/`agent_needs_input`(2)/`agent_completed`(1) 四种，无 error 类；最近 400 条 Stop/Notification 的 `last_assistant_message` 无一条是报错原文。规模：199 个会话里 25 个中招、共 70 条；报错前静默 p50=4s / p90=739s / max=3457s（长尾 = ESC 唯一有用的窗口）。文本三类语义：`500 litellm.InternalServerError - Connection error` / `Request timed out` = 可重试；`402 ... Insufficient Balance` = 重试无用；`400 ... exceeds the model's maximum context length` / `Prompt is too long · automatic compaction failed` = 须 /compact 或新会话。据此**会话中断**能力的语义边界 = ESC 只救在途重试，报错落定后该重发（规则见 CLAUDE.md）。
- **会话中断落地**（6e64d1e 服务端 + 64add74 web）：`POST /sessions/:id/interrupt` 打一记 ESC；停止按钮落事件链最新组头折叠条，不按 running 门控。ESC 裸字节可达实测：`wezterm cli send-text --no-paste` + raw 模式 stdin 收到 `1b`。CLI 不提供停止命令（用户裁决「cli 不需要」）。
- **终态驻留 + 未回执闸定案**：delivered/injected/succeeded 在 `settledAt`+60s 内留在在途视图展示 `via`/`acked`；prompt 送达 `ackStallMs`（缺省 120s）未回执、或中继/终端投递失败 → 该会话队列冲洗暂停（`flushSession` 闸），成因消息标 `stalled`。规则全文见 CLAUDE.md「消息/编排域」。
- **中继启动开关实测（本机）**：`--strict-mcp-config --disable-slash-commands` 恒开（实测仍能正确应答、工具白名单照旧）；`--bare` 快 ~9×（38s→2.5s）但当版本 `--tools` 白名单失效（实测中继跑去调 WebSearch 不投递）+ 只认 API key（OAuth 认证失败）——查到但不可用，禁用。
